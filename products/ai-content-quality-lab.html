The problem

A polished answer can still be incomplete.

Teams need more than an overall score to decide whether generated content is ready. A fluent answer may omit access restrictions or invent a product capability. This lab makes the evidence and routing logic visible so a reviewer can see why an output passes—or why it should stop.

Design decision

Start with deterministic rules and small, inspectable examples. Add claim evidence, regression gates and a dashboard before connecting a model provider.

What this demonstrates

Content strategy translated into evaluation requirements, product release controls and knowledge architecture. The outcome is a reproducible prototype, not a calibrated enterprise benchmark.

System design

From approved facts to reviewable decisions.

The offline pipeline evaluates saved candidates, runs a retrieval demo and exports graph context. Retrieval and graph outputs are demonstration artifacts; they do not generate the saved candidates.

The six versions

One system, built in layers.

V1 / Transparent scoringGroundedness 25%, factual consistency 20%, completeness 20%, relevance 15%, brand/tone 10%, citation support 10%.
V2 / Claims and evidenceSentence splitting, lexical evidence matches and a provider-neutral judge prompt interface.
V3 / Regression gatesThree expected routing decisions catch behavior changes before release.
V4 / Quality dashboardStreamlit views for scores, decisions and claim-level evidence.
V5 / RetrievalA local lexical retriever keeps the example runnable without a vector database.
V6 / Knowledge graphExplicit relationships connect audiences, needs, products, messages and evidence.

Interactive results / saved evaluation artifacts

Inspect the decision behind the score.

Choose a synthetic output to inspect its actual saved scores and evidence. This browser view explores the packaged results; it does not call an AI model.

Routing policy: factual consistency or groundedness below 2.5/5 forces FAIL. Completeness below 3.5/5 requires review when the total is at least 70, otherwise FAIL. Remaining outputs pass at 85+, review at 70–84.9, and fail below 70.

Limits: similarity is not semantic entailment; factual checks cover selected phrases; citation support is a heuristic rather than a citation-verification service. These four examples do not establish real-world accuracy.

Run it yourself

From download to a quality decision.

  1. Download the project ZIP using GitHub’s download control and extract it.
  2. Open a terminal inside ai-content-quality-lab-complete. Create an isolated environment, install dependencies and run the pipeline.
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python src/run_pipeline.py
python tests/regression_suite.py
streamlit run dashboard/app.py

On Windows, activate with .venv\Scripts\activate. No API key is needed for the default pipeline.

1. Inspect the inputs

Read data/source_brief.json for approved facts, required points and prohibited language. Compare the four synthetic candidates in data/generated_outputs.json.

2. Trace scores to evidence

Open results/evaluation_results.csv and results/claim_evidence.json. Inspect the incomplete output: its aggregate score exceeds 85, but completeness is only 2/5, so the guardrail holds it for review.

3. Test a change

Edit a candidate or required point, rerun the pipeline and then the regression suite. Diagnose a changed decision before changing the golden expectation. The suite checks three examples; add more cases for omissions, contradictions, empty inputs and adversarial language.

4. Explore retrieval and graph context

Inspect results/rag_demo.json and results/knowledge_graph_context.txt. Change the corpus or graph, rerun, and compare the context. Connecting that context to live generation is a future integration step.

5. Adapt responsibly

Replace the synthetic brief with approved, non-sensitive content. Calibrate weights, thresholds and review decisions against expert judgments. Connect an approved model through src/llm_judge.py only after defining credentials, access and data-handling controls.

What comes next

Calibrate before scaling.

The next step is a larger expert-labeled evaluation set, including retrieval errors and misleading claims. Production readiness also requires permission-aware retrieval, versioned prompts and evaluators, human override records, audit logs, and cost and latency monitoring.
