Agentic workflow framework

Agentic Technical Program Management

A portable operating system for turning incomplete program information into a reviewable plan—and keeping that plan honest as the evidence changes.

By Sharmila (Das) Rammohan
2026
Framework + prompt kit

High-level summary

This framework uses an AI assistant as a structured program coordinator. It creates a charter, milestones, risks, issues, dependencies, actions, and decisions; maintains stable state across reviews; and prepares concise escalations for accountable people.

It is intentionally portable. It requires no code, integrations, or background process. One assistant runs seven specialist perspectives sequentially, checks its own output, and stops when human authority or missing evidence is required.

How the workflow operates

Seven specialist perspectives

The framework does not pretend that seven autonomous agents are operating. One assistant adopts only the perspectives needed for the current command:

  1. Intake analyst: extracts evidence, preserves sources, and labels uncertainty.
  2. Program architect: defines outcomes, scope, authority, milestones, and acceptance evidence.
  3. Dependency and risk analyst: maintains separate risk, issue, dependency, action, and decision registers.
  4. Delivery analyst: reconciles updates against stable IDs and separates baselines from forecasts.
  5. Decision facilitator: frames options, consequences, recommendations, authority, and timing.
  6. Readiness reviewer: evaluates launch evidence and distinguishes outputs from measured outcomes.
  7. Quality reviewer: checks traceability, ownership, status logic, dependency order, and historical consistency.

What the review found

Evidence discipline

Material claims trace to named sources or remain visibly labeled as assumptions, proposals, or unknowns.

Decision integrity

Requested dates, approved baselines, and current forecasts stay separate. A new idea is never treated as an approved commitment.

State continuity

Stable IDs prevent duplicate risks and actions, while change records preserve what changed and why.

Human accountability

The assistant drafts ticket changes, messages, assignments, and launch recommendations but does not claim authority or execution.

Realistic status

Missing or stale evidence remains unknown. Lack of updates never becomes “on track.”

Practical portability

The complete program state is valid JSON, so a team can move the workflow between approved assistants without relying on hidden memory.

A five-minute start

  1. Open an AI assistant approved for your program information.
  2. Paste the complete workflow prompt into a new conversation.
  3. Fill in the intake with the business outcome, scope, teams, evidence, authority, and dates you know.
  4. Run START and review the proposed charter, ownership, and plan.
  5. Save the returned state. On the next review, paste the prompt, saved state, and new evidence, then run UPDATE.

Worked example

The included fictional example begins with a preferred launch date, an API dependency, a five-day integration estimate, and a mandatory security review with unknown timing. The workflow correctly reports the initial status as unknown rather than inventing a schedule.

A weekly update moves the API forecast later and reveals that the earliest mandatory review occurs after the requested launch. The framework marks the program at risk, keeps the requested date unchanged, leaves the final forecast unknown, and raises a decision between seeking an earlier review slot and revising the target.
