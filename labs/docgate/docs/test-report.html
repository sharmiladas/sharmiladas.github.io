Documented client commands

Four additional requests were executed against a running server on port 8787: the Python file client for both rewrite fixtures, the quickstart curl request, and the blank-document troubleshooting request. Results matched the documented finding counts and status codes. Sanitized, actual responses are saved in recorded-local-results.json.

What testing revealed

Code examples can contain heading-like lines. Counting those as document structure would produce false negatives, so the implementation excludes triple-backtick fences and includes a regression case. A request's UTF-8 JSON size is different from its decoded character count, so the API enforces and documents both limits. Provider responses can mix text and other blocks, so the client extracts text blocks and rejects responses without usable text. These are verified behaviors, not claims that a defect was discovered in a prior employer system.

Unverified behavior

No live Claude call was made. Fixture tests verify client handling, not actual provider compatibility, model quality, or billing. Python 3.11 and 3.13 are configured in the included CI workflow but were not executed here. Slow-body timeout recovery, concurrent load, and full CommonMark compatibility were not exercised. The code is a local sample, with no production deployment, durability, or authentication claim.
