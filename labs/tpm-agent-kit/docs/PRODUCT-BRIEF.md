# Baseframe TPM Agent: product brief

## Problem
Program leads must reconcile delivery signals across notes, trackers, and reviews. Missing handoffs and late decisions can remain hidden behind lists of completed activities.

## Recommendation
Begin with a file-based TPM agent that maintains evidence-linked program state and produces decision-oriented reviews. Pilot against one program before investing in live connectors or a hosted interface.

## Users and job
Technical program leads managing multiple engineering and content workstreams. Their job: know whether the next milestone is credible, what threatens it, and who needs to decide by when.

## MVP boundary
Implemented: instructions, eight workflows, reusable registers, local setup, fictional demo, evaluation scenarios. Future: tracker adapters, source freshness automation, graph visualization, scheduling, access controls, and hosted UI. These future features are not included in version 0.1.

## Proposed pilot measures
Measure time to prepare a weekly review before/after; unsupported status claims; percentage of active dependencies with accepted handoffs; time from risk detection to decision; duplicate actions after reprocessing. Establish actual baselines before making benefit claims. Target zero fabricated approvals and zero unauthorized messages.

## Portfolio positioning
Describe this as “Designed and built a reusable TPM agent operating kit with evidence-linked program registers, dependency reviews, and release controls.” Only add adoption, time savings, or delivery impact after measuring a real pilot. The fictional knowledge-platform example does not establish production impact.
